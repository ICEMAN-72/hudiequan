# 蝴蝶泉 · 养成系统设计与架构

> 版本 v2.0 · 2026-11-03
> v0.1（通用经验值 + 六品种解锁）已废弃，本版按「一眼泉养一只蝶」重写。

---

## 0. 一句话

点击左上角的蝴蝶标志，打开一处泉。泉眼在你完成任务时涌动，泉水养一只蝶，
从卵到幼虫到蛹到成虫。成虫之后飞回主界面，偶尔停在任务卡的边沿。

---

## 1. 这一版改了什么

v0.1 是一套通用经验值系统：经验、等级、六种品种靠行为分布解锁、可切换。
问题是它把「成长」和「收藏」混在一起，用久了会一直在比较哪个品种更强。

v2.0 只保留一件事：**泉水**。一泉只养一只，一代成虫就换下一枚卵。
多只蝶来自「养了几代」，不是抽卡解锁 —— 这正好对应你说的
「每个卵可以孵化出颜色不同、花纹不同的蝴蝶」。

被删掉的：品种解锁、可切换外观、连续天数、排行榜、每日任务目标。
被保留的：不惩罚、不打扰、可解释、可关闭（v0.1 的四条原则依然成立）。

---

## 2. 三条硬约束

| 约束 | 含义 | 为什么 |
|---|---|---|
| **泉水只增不减** | 撤销任务、删除任务、清空列表，水位都不回落 | 一旦会掉，你就会开始怕点错，工具变成考官 |
| **泉水由任务推导，不另记账本** | 不保存「每个任务给了多少分」 | 账本会和任务失同步：导入、云端拉取、恢复快照都会对不上 |
| **动画永不拦截点击** | 主界面飞行层 `pointer-events: none`，面板内动画不遮输入框 | 反馈一旦挡手，就会被关掉，然后整个系统白做 |

第二条约等于整个架构的地基，第 6 节展开。

## 3. 核心循环与数值

### 3.1 泉水怎么来

每完成一个任务计一次分，按象限给不同权重（没有惩罚项，只在 11~16 之间浮动）：

| 情况 | 泉水 |
|---|---|
| 根任务 · 立即执行 | 16 |
| 根任务 · 计划安排 | 15 |
| 根任务 · 委托处理 | 13 |
| 根任务 · 尽量减少 | 11 |
| 子任务 | 4 |
| 周期任务当期完成 | 额外 +2 |
| 某父任务的子任务当天全部做完 | 额外 +6（收尾） |

设计意图：

- **子任务只值 4 分**，因为把一件事拆成五步不该等于做了五件事；
  但「拆开并全部做完」有 6 分收尾奖励，奖励的是把事推完，不是把事切碎。
- **象限之间只差 5 分**，不做价值判断。你放东西进「尽量减少」不是罪。
- 不给「今天完成了 N 个」额外奖励 —— 那会变成每日指标。

### 3.2 阶段阈值

| 阶段 | 泉水区间 | 一天 3 个任务的进度 |
|---|---|---|
| 卵 | 0 – 119 | 第 3 天 |
| 幼虫 | 120 – 399 | 第 9 天 |
| 蛹 | 400 – 899 | 第 20 天 |
| 成虫 | 900 | 第 20 天前后 |

900 是一个刻意很高的数：形态变化只有 3 次，太快通关就只剩空池子。
按每天 3 个「立即执行」算，约 45 泉水/天，成虫大约在第三周。

### 3.3 上限与防刷

- **每日上限 150 泉水**（`finishedAt` 落到本地日期分组后求和，再逐日封顶）
- 反复勾选 / 取消同一个任务：因为水位只增不减，来回点无法刷分
- 删除已完成任务：不扣分（水位已记在 `floor` 里）
- 导入几百条历史任务：按天封顶，不会一夜通关

### 3.4 首次开启：历史怎么算

第一次点开泉时，把历史已完成任务折算成泉水，但**最多折 60**。
理由：完全不算，会觉得以前的努力白费；全算，你三个月的历史会当场换出
两三只成虫，卵和第一次进化直接被跳过 —— 那才是真的毁掉体验。

60 刚好让第一枚卵走到一半，两天内必然看到第一次「卵 → 幼虫」。
面板里会写明：`你完成过 187 个任务，泉水记得它们。`

## 4. 界面

### 4.1 入口

左上角 `ButterflyMark` 外面包一层按钮，`title="蝴蝶泉"`。
hover 时 logo 轻微振翅 0.4s，作为「这里可以点」的唯一提示，不加徽章不加红点。

### 4.2 泉面板（52rem × 约 34rem，`Modal tone="panel"`）

```
┌────────────────────────────────────────────────┐
│ 蝴蝶泉                        第 1 代 · 紫斑  × │  64px
├────────────────────────────────────────────────┤
│                                          ·  ·  │
│        （光柱）        成虫在飞                 │
│  ～～～～～～～～～～～～～～～～  水面           │  场景 300px
│      ◎ 泉眼          [ 卵 ]                    │
│  ▁▁▁▁▁▁ 池底卵石 ▁▁▁▁▁▁                        │
├────────────────────────────────────────────────┤
│ 卵 · 72 / 120                    今日 +45 · 150 │  88px
│ ▓▓▓▓▓▓▓▓░░░░░░░  距离幼虫还差 48 泉水            │
├────────────────────────────────────────────────┤
│ 泉里的蝶  ● ● ○ ○ ○   每一代颜色都不同           │  56px
└────────────────────────────────────────────────┘
```

- 场景是**侧视剖面的水池**：上方空气与光柱，下方水体，中央泉眼。
- **水位 = 这一代蝶的成长进度**，`11% ~ 100%` 映射到水体高度。
  下限 11% 是为了水池在任何时刻都不显得干涸。
- 进度条在底部，同时给出「还差多少」的具体数字 —— 可解释原则。

### 4.3 泉眼涌动（1.2s，任务完成或打开面板且有增量时触发）

```
0.00s  水面静止
0.05s  泉眼中心亮度 +20%，像睁了一下眼
0.10s  水柱升起 14px，三圈涟漪从泉眼扩散（0.9s 内依次错开 0.15s）
0.15s  6~10 个水泡上升，随机横向漂移
0.30s  水位线升高到新值（600ms，cubic-bezier(.22,1,.36,1)）
0.45s  浮字「+15 泉水」从泉眼上方升起，1.0s 淡出
1.20s  回到静息
静息  每 3.2s 涌一次小幅度呼吸（40% 强度），让池子不是一张图
```

同一秒内完成多个任务：合并成一次涌动，浮字显示合计值。

### 4.4 主界面飞行层

只有 `adult` 阶段才渲染，最多 2 只（超出的只待在池子里）。

- 挂载在 App 根：`position: fixed; inset: 0; z-index: 20; pointer-events: none`
- 落点来自 `[data-perch]` 元素：四个 tile 的外框四角 + 顶栏右端；
  任务卡也带 `[data-perch]`，但只取视口内的。
- 状态机：`perch(8~18s) → takeoff(0.25s) → fly(1.1~1.6s 二次贝塞尔) → land(0.2s)`
- 飞行中带 ±6px 的上下浮动与 ±8° 的姿态倾斜，避免像直线平移的贴纸。
- 完成任务时：监听 `hudiequan:task-done`，最近的一只飞向那张卡片的右上角，
  停 1.2s、振翅两次，再回到航线。**不弹任何数字** —— 主界面保持安静，
  数字只在泉面板里出现。
- 不做点击蝴蝶的交互：飞行层是 `pointer-events: none`，点击会穿透到下面的卡片，
  与其拦掉一次正常的点击，不如让入口只有 logo 一个。

### 4.5 新手指引（只出现一次，3 步）

全部在面板内完成，不做跨层箭头（跨层高亮最容易在布局改动后错位）：

1. 泉眼吐出一枚卵（1.2s），文字：「泉眼给了你一枚卵。它要靠泉水长大。」
2. 文字：「每完成一个任务，泉眼会涌一次，泉水就多一点。」
   下方示例条：`完成 1 个任务 → +15 泉水`
3. 文字：「攒够泉水，它会从卵变成幼虫、蛹，最后成蝶。成虫之后会飞回主界面。」
   按钮：「开始养它」

引导结束时 `onboardStep = 4`，永不再现。设置里有「再看一遍新手指引」。

### 4.6 关闭时的行为

面板关掉后，泉水照常累积。下次打开时若水位比 `seenTotal` 高，
补播一次涌动，浮字显示这段时间的合计（而不是每次任务都补播）。

## 5. 一只蝶是怎么长出来的

### 5.1 四个形态

| 形态 | 画法 | 动 |
|---|---|---|
| 卵 | 半透明椭球，内部一团暖光 | 内部脉动 3.6s，极慢 |
| 幼虫 | 五节身体 + 头，半透明青绿 | 沿石面缓慢蠕动，4s 位移 6px |
| 蛹 | 棱角外壳，挂在泉眼旁的石沿 | 轻微摆 ±3°，5s；进度过 80% 后内部透光 |
| 成虫 | 参数化蝴蝶（翅形 × 花纹 × 色板） | 振翅 1.4s 一周期，落定时闭合 |

### 5.2 配色与花纹：由 seed 决定

每枚卵生成时取一个随机 `seed`，映射到：

- **色板**（8 组预设，做过明度控制，不会出荧光色）
  紫斑 `#7C3AED / #EC4899`、青绢 `#0EA5E9 / #67E8F9`、琥珀 `#F59E0B / #FDE68A`、
  月白 `#E9E4F5 / #C4B5FD`、黛蓝 `#1E3A8A / #60A5FA`、珊瑚 `#FB7185 / #FECDD3`、
  苔绿 `#059669 / #A7F3D0`、墨玉 `#3F3D56 / #A78BFA`
- **花纹**（4 种）：斑点 / 横带 / 眼斑 / 渐变
- **翅形**（3 种）：圆翅 / 燕尾 / 尖翅

3 × 4 × 8 = 96 种组合，五只以内几乎不会撞色。
名字由「色板名 · 花纹」自动生成，例：`青绢·眼斑`、`琥珀·燕尾`，可手动改名。

### 5.3 池子上限

最多 5 代。满了之后泉眼停止产卵（静息态变慢），不做任何提示与惩罚 ——
只是不再有新卵，已经养着的蝶照样在飞。

## 6. 数据模型与算法

### 6.1 为什么是「推导」而不是「记账」

如果给每个任务记一笔「它给了 15 分」，那么这份账本必须和任务列表永远一致：
导入备份、从云端拉取、从快照恢复、删除任务、修改象限 —— 每一步都要同步两份数据。
漏掉任何一步，就会出现「任务还在，分没了」或者「任务没了，分还在」。

所以：**泉水 = f(当前任务列表)**，一个纯函数。任务就是唯一的真相。
唯一存下来的是 `floor`（历史最高水位），它的作用只有一个 —— 让水位不因删除而回落。

代价是「某个任务具体给了多少分」不容易逐条追溯，但那是我们要避免的东西
（可解释指的是规则可解释，不是每一笔流水账）。

```ts
// src/lib/butterfly/spring.ts
export function taskSpring(task: Task): number;              // 单任务分值
export function computeSpring(tasks: Task[]): {
  total: number;      // 历史累计（逐日封顶后求和）
  today: number;      // 今天的量（已封顶）
  capped: boolean;    // 今天是否已到上限
  completed: number;  // 历史完成数，用于文案
};
export function stageOf(xp: number): Stage;                  // 单只蝶内部进度 → 形态
export function stageProgress(xp: number): number;           // 0~1，用于水位
```

`computeSpring` 是纯函数，可以直接单测，不依赖 React。

### 6.2 Store

```ts
// src/store/butterflyStore.ts  →  persist 到 'hudiequan-butterfly'
export interface ButterflyRecord {
  id: string;
  seed: number;       // 决定色板/花纹/翅形，永不改
  bornAt: number;
  name?: string;      // 用户改过的名字
}

interface ButterflyState {
  butterflies: ButterflyRecord[];
  floor: number;      // 水位下限，只增不减
  seenTotal: number;  // 上次在面板里看到的水位，驱动补播
  onboardStep: number; // 0 未开始 · 1..3 引导中 · 4 完成
  initIfEmpty: () => void;                // 首次：产第一枚卵 + 折 60 历史
  ensureGeneration: (n: number) => void;  // 按水位补足代数，上限 5
  rename: (id: string, name: string) => void;
  setSeen: (n: number) => void;
  resetPond: () => void;                  // 设置里的「重新养」
}
```

注意：`butterflies` 里**不存 stage，也不存 xp**。这两个都是 `total` 与序号的函数：

```
第 i 只蝶的进度 = clamp(total - i * 900, 0, 900)
当前在养的是第一只未满 900 的
```

这样导入一份旧备份、或者换台电脑，也永远算得出正确的形态。

### 6.3 数据流

```
tasks (zustand, 已有)
   │
   ├─ computeSpring(tasks) ──▶ { total, today, capped }
   │                              │
   │                              ├─▶ 泉面板：水位 / 阶段 / 进度 / 今日
   │                              └─▶ floor 兜底（butterflyStore）
   │
   └─ cycleStatus / batchComplete / updateTask
          └─ dispatch('hudiequan:task-done', { taskId })
                    │
                    └─▶ 飞行层：飞到那张卡片停 1.2s

butterflyStore.butterflies ──▶ 飞行层只渲染 adult 的（最多 2 只）
```

`taskStore` 只负责**派发事件**，不计算泉水，也不写蝴蝶数据 —— 保持任务层干净。
否则任务 store 会依赖蝴蝶 store，测试和迁移都会变复杂。

## 9. 备份、导出与同步

- 自动备份 payload：`{ tasks, butterfly: { butterflies, floor, seenTotal, onboardStep } }`
- 手动导出同样是这份结构；导入时若文件里没有 `butterfly`，**保留本机现有的蝶**，
  只导入任务（旧备份不能把蝶清空）
- 云同步仍沿用现在的手动上传 / 拉取；蝴蝶跟随任务一起走，
  冲突策略先按「后写覆盖」，不单独做合并

## 10. 性能与降级

- 全部用 SVG + CSS 动画，不引 canvas / 粒子库
- 飞行层 `requestAnimationFrame` 直接改 `transform`，不用 React state 驱动
  （否则每秒几十次重渲染）
- `document.hidden` 时暂停 rAF；`prefers-reduced-motion: reduce` 时
  只有淡入淡出，水面静止，蝴蝶停在角落不动
- 设置里「减少动态」独立于系统设置，一键让涌动变成水位直接跳到新值

## 11. 构建顺序

| # | 内容 | 完成标准 |
|---|---|---|
| 1 | `spring.ts` + `traits.ts` + `stages.ts` + 单测 | `npm test` 全绿，分值/阶段边界断言通过 |
| 2 | `butterflyStore` + 首次初始化 + 代数补足 | 刷新后蝶与水位不变；导入旧数据不炸 |
| 3 | 泉面板（场景 + 四形态 + 水位 + 引导） | 点 logo 能开；引导只出现一次；水位随任务变化 |
| 4 | 飞行层 + 任务完成事件 | 成虫才出现；停在卡片边沿；不挡点击 |
| 5 | 备份 / 导出 / 设置开关 + 截图验收 | `npm run shots` 出亮色、深色、四形态、飞行四组图 |

## 12. 验收

- 单测覆盖：分值边界、逐日封顶、900 处换代、卵/幼虫/蛹/成虫边界、seed 稳定性
- 截图覆盖：泉面板（卵 / 幼虫 / 蛹 / 成虫 × 亮暗）、引导三步、主界面有蝶
- 回归：`tsc -b` / `oxlint` / `npm test` / `npm run build` 全过

## 13. v1 明确不做

- 品种解锁、抽卡、图鉴切换
- 喂食、抚摸、点击蝴蝶互动
- 蝴蝶说话、天气、昼夜光照变化（夜间只会让翅膀闭合，不引入时间系统）
- 连续天数、每日目标、任何形式的惩罚
- 云同步的经验冲突合并

## 14. 仍需你拍板

1. **首只蝶的名字**：自动生成（「紫斑」）还是第一次成蝶时让你取？
2. **主界面飞行的数量**：2 只（安静）还是跟随代数全部放出来（热闹，但会挡视线）？
3. **泉面板尺寸**：52rem（和灵感一致）还是 46rem（更紧凑，场景更矮）？
