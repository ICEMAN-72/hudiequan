# 蝴蝶养成系统 · 产品方案

> 版本 v0.1 · 2026-10-27
> 目标：解决「用起来有点无聊」——让工具对使用者有回应，而不只是被动记录。

---

## 一、先想清楚：为什么需要它

任务管理工具的通病是**单向**的：你输入，它存储。它不会因为你今天很努力而有所不同，也不会因为你三天没来而有什么变化。用久了就退化成一张表格。

养蝴蝶不是为了加一个"积分商城"。它的作用有三个，按重要性排：

1. **让「使用这个工具」这件事有连续性** —— 蝴蝶会成长、会变化，所以你会记得它。
2. **给完成动作一个即时的、非文字的回馈** —— 勾选变成「有东西飞过来」，而不是「一行字变灰」。
3. **让界面在任何时刻都有一点生命** —— 静置的时候屏幕不是死的。

**明确不追求**：不追求让人上瘾、不做排行榜、不做社交、不做限时活动。这是个人工具，不是游戏。

---

## 二、设计原则（这几条决定所有细节）

| 原则 | 含义 | 反面例子 |
|---|---|---|
| **不惩罚** | 断签、低迷、清空任务都不扣经验、不降级、不死 | 连续 7 天不打开，蝴蝶饿死 |
| **不打扰** | 动画总时长 ≤ 2 秒，不遮挡内容，可一键关掉 | 完成任务弹全屏庆祝 |
| **不制造焦虑** | 不显示"今天必须完成 X 个"，不显示倒计时 | 未完成任务时显示"你又拖延了" |
| **可解释** | 每一分经验都能查到从哪来 | 神秘加成、随机奖励 |
| **可关闭** | 设置里一个开关全部关掉，不影响任何功能 | 强制展示成长动画 |

## 三、核心循环

```
完成任务
   ↓  +经验（有每日上限，防刷）
经验累积 → 达到门槛 → 形态变化（卵→幼虫→茧→成蝶）
   ↓                        ↓
即时反馈动画            外观永久改变 + 品种解锁
   ↓                        ↓
「它在陪我」的感知 ← ← ← ← ←┘
   ↓
更愿意打开 → 更多任务被完成
```

关键点：**形态变化是不可逆的、稀有的**。整个生命周期只有 3 次形态变化，之后靠品种解锁维持新鲜感。门槛要足够高，否则一天就通关了，第二天就没了期待。

---

## 四、成长阶段

| 阶段 | 经验区间 | 形态 | 视觉 | 预估到达 |
|---|---|---|---|---|
| 卵 | 0 – 119 | 一枚半透明的小卵 | 静止，偶尔内部微弱脉动 | 第 1 天 |
| 幼虫 | 120 – 399 | 一条小虫 | 缓慢蠕动，会沿着面板边缘爬 | 约第 3 天 |
| 茧 | 400 – 899 | 悬挂的蛹 | 轻微摇摆，第 800 经验起内部透出微光 | 约第 10 天 |
| 成蝶 | 900 + | 蝴蝶 | 见第六节行为设计 | 约第 25 天 |

> 按每天完成 5 个普通任务（约 50–70 经验）估算。任务多的人会更快，这是合理的——投入多的人应该更快看到变化。

**成蝶之后**：每再累积 500 经验解锁一个新品种，共 6 种。已解锁的可随时切换（不消耗经验）。

## 五、经验规则

### 5.1 获取

| 行为 | 经验 | 说明 |
|---|---|---|
| 完成普通任务 | +10 | 基础值 |
| 完成「立即执行」象限的任务 | +15 | 重要且紧急，多给一点 |
| 完成「计划安排」象限的任务 | +13 | 重要不紧急 |
| 完成「委托处理」/「尽量减少」 | +8 | 价值较低 |
| 该任务有子任务，且全部完成 | +5 | 拆解能力的奖励 |
| 完成周期任务（当期） | +12 | 长期坚持比一次性更值钱 |
| 每日复盘完成 | +10 | 每天一次 |
| 当天全部未完成清零 | +20 | 「清空」奖励，一天最多一次 |

### 5.2 上限与防刷

- **每日软上限 200 经验**，超过后不再增加（防止为了刷经验疯狂拆任务）
- **同一任务当天只计一次分**：用一个 `todayScored: Set<taskId>` 记录，反复 done↔undo 不重复给
- **删除任务不给经验**，且删除已计分的任务也不扣（避免负反馈）
- 批量完成按逐个计算，同样受每日上限约束

### 5.3 不做的事

- ❌ 不扣经验（错过了就错过了）
- ❌ 不做"连续 N 天"的惩罚机制，只做**展示**（「连续 12 天」是个记录，不是任务）
- ❌ 不做随机奖励（不可解释，会让人怀疑规则）
- ❌ 不做任务过期扣分

## 六、蝴蝶的行为设计

这是「不无聊」的主要来源。分三种状态：

### 6.1 栖息（常态，占 95% 时间）

- 停在**界面边框、面板圆角、或标题栏边缘**，不落在任务卡片上（不挡内容）
- 翅膀缓慢开合：`4s` 一个周期，张角从 15° 到 65°
- 1–3 只同时存在（按累计经验决定数量：900 经验 1 只，2000 经验 2 只，3500 经验 3 只）
- 每 3–5 分钟**随机换一次落点**，飞行路径为二次贝塞尔曲线，时长 1.2s
- 夜间（22:00–06:00）翅膀闭合，几乎不动 —— 省电，也符合"该休息了"的暗示

### 6.2 舞台：完成任务时（0.8s + 2s 后离开）

```
0.0s  任务被勾选
0.1s  最近的一只蝴蝶从栖息点起飞
0.5s  落在刚完成的那张卡片右上角
0.6s  振翅两次（快，0.15s 一次）
0.9s  化成一串小光点，沿曲线飞向经验条
1.4s  经验条增长，浮出 "+10"
2.0s  蝴蝶飞回原栖息点或新的落点
```

- 全程 `pointer-events: none`，不阻塞下一次点击
- 如果 2 秒内连续完成多个任务，**合并**为一次：只播一次动画，经验条一次性增长

### 6.3 互动（鼠标靠近）

- 鼠标进入蝴蝶 60px 范围 → 蝴蝶飞走（500ms 内离开），停到另一个角落
- 这是唯一的主动交互，不做"点击喂食"之类的养成操作（那是另一个系统的复杂度）
- 点击蝴蝶 → 打开养成面板

### 6.4 性能与降级

- 用 CSS `transform` + `requestAnimationFrame`，不用 canvas，不用粒子库
- 同时最多 3 只，离屏时暂停动画（`IntersectionObserver`）
- `prefers-reduced-motion: reduce` → 蝴蝶静止停在角落，形态变化改为淡入淡出
- 设置里提供「减少动画」开关，独立于系统设置

## 七、品种（成蝶后的长期目标）

品种由**你的工作风格**决定，而不是随机 —— 这样它反映的是你，不是抽卡。

| 品种 | 解锁条件 | 视觉 |
|---|---|---|
| 紫斑蝶 | 默认（第一次成蝶） | 紫底 + 粉色斑纹，品牌色本体 |
| 凤蝶 | 「立即执行」完成数占总完成数 ≥ 40% | 深紫近黑，翅膀长、飞得快 |
| 绢蝶 | 「计划安排」完成数占比 ≥ 50% | 米白半透明，飞得慢 |
| 灰蝶 | 「委托处理」完成数占比 ≥ 30% | 小、灰蓝，停得久 |
| 粉蝶 | 「尽量减少」完成数占比 ≥ 25% | 浅粉，动作轻盈 |
| 夜光蝶 | 累计完成 500 个任务 | 深底带微光，夜间特别明显 |

- 前 5 种成蝶即可判定（按历史完成分布）
- 第 6 种是最长期的，给重度用户一个远处的东西
- 判定后可在图鉴里切换，不影响经验

## 八、界面

### 8.1 常驻位置

蝴蝶**直接存在于主界面**，不占用任何布局空间（`position: absolute` 在整个 app 容器内，`pointer-events: none` 除了蝴蝶本身）。

不做独立的"宠物栏"。宠物栏会把本来就不够的空间再切一块走。

### 8.2 养成面板（点击蝴蝶呼出）

用现有的 `Modal` 组件，宽度 28rem：

```
┌──────────────────────────────────┐
│  [大蝴蝶图形，约 96×96]           │
│  小紫  ·  茧  ·  Lv.3            │
│  ▓▓▓▓▓▓▓░░░░░░  620 / 900        │
│  距离成蝶还差 280 经验            │
├──────────────────────────────────┤
│  今天 +65 经验                    │
│  ✓ 完成 5 个任务        +58       │
│  ✓ 完成每日复盘         +10       │
│  （今日上限 200，已用 65）        │
├──────────────────────────────────┤
│  连续 12 天 · 累计完成 187 个任务 │
├──────────────────────────────────┤
│  图鉴  ●○○○○○   已解锁 1 / 6     │
├──────────────────────────────────┤
│  [改名]        [减少动画 ○]       │
└──────────────────────────────────┘
```

### 8.3 经验条（常驻）

放在顶栏右侧、统计数字旁边，一条 80px 的细进度条 + 阶段图标。不做成大片区域。

## 九、数据模型

```ts
export type ButterflyStage = 'egg' | 'larva' | 'cocoon' | 'adult';

export interface Butterfly {
  /** 累计经验，只增不减 */
  xp: number;
  /** 由 xp 推导，存下来是为了动画能知道「刚刚变了」 */
  stage: ButterflyStage;
  /** 成蝶后确定的品种 id */
  species: string;
  /** 用户可改的名字 */
  name: string;
  /** 首次成蝶的时刻 */
  hatchedAt?: number;
  /** 连续使用天数（只展示，不惩罚） */
  streak: number;
  lastActiveDay: string;        // 'YYYY-MM-DD'
  /** 当日已得经验，跨天清零 */
  todayXp: number;
  todayDay: string;
  /** 当日已计分的任务 id，防刷 */
  todayScored: string[];
  /** 已解锁的品种 id */
  unlocked: string[];
}
```

- 存进现有 `settingsStore` 之外单独一个 `butterflyStore`，`persist` 到 `hudiequan-butterfly`
- **必须写进备份 payload**（`BackupPayload` 增加 `butterfly` 字段），否则换电脑归零，反而更挫败
- 跨天判断统一走 `src/lib/date.ts` 的 `todayStr()`，禁止 `toISOString()`

## 十、交付顺序

| 阶段 | 内容 | 判断标准 |
|---|---|---|
| **L1** | 蝴蝶栖息 + 完成任务时的反馈动画 + 经验条 | 用一周，看"有没有它"是否影响心情 |
| **L2** | 四阶段形态 + 养成面板 + 数据持久化与备份 | 能看到从卵到蝶的完整过程 |
| **L3** | 品种系统 + 图鉴 + 夜间行为 | 成蝶之后还有目标 |

**L1 是验证，不是半成品。** 如果 L1 做完你觉得"好像也就那样"，L2/L3 就不该做 —— 这说明问题不在缺少奖励，而在别处（可能是任务本身太多、或者分类不清）。

## 十一、风险清单

| 风险 | 应对 |
|---|---|
| 动画打断操作 | 全部 `pointer-events: none`，2 秒内合并播放 |
| 分心 | 默认只播"完成任务"这一种动画，不做随机游荡之外的花样 |
| 经验值丢失 | 纳入备份 payload，与任务同生共死 |
| 换设备经验不同步 | 明确告知：经验绑定本机，同步功能上线后再协商 |
| 蝴蝶挡内容 | 只在边框和角落栖息，永不落在任务区 |
| 性能 | 最多 3 只，离屏暂停，`reduced-motion` 全降级 |
| 变成负担 | 无惩罚、无排行、无每日目标；连续天数只展示 |

## 十二、待定问题（需要你拍板）

1. **名字**：默认叫「小紫」还是让用户第一次打开时命名？
2. **初始阶段**：第一次打开就是卵，还是给一个 0 经验的卵并说明"完成任务让它孵化"？
3. **经验值可见性**：顶栏常驻经验条，还是只在养成面板里看？常驻会更"在场"，但也更占空间。
4. **断签文案**：连续天数断了，要不要给一句温和的提示（"好久不见"），还是完全不提？
